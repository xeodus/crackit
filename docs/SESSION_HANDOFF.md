The user wants a polished, discreet experience comparable in quality to Cluely, using original design and independently implemented capabilities. A web app will provide signup/login, subscriptions, downloads, entitlements, and account/history controls; the interview capture client is a **desktop app**, not a browser extension. Expand to Windows, then selected Linux distributions only after macOS works. Broad meeting-suite/CRM/mobile parity is no longer a launch requirement. “Perfect results,” universal interview success, and universal screen-share invisibility are aspirations, **not verified claims**. See the detailed first-release surfaces and exit gates in `research/05-interview-first-plan.md`.

The 30-minute run’s native report shows one >100 ms mic timestamp gap and zero system >100 ms gaps, while the Python transport reports one discontinuity for each source. These counters use different thresholds and locations; investigate before attributing cause. Queue peaks in the JSON describe only the surviving final decoder epochs; earlier reset epochs have no queue summary in that report. The longer native duration than the 1,805-second request and simultaneous queue growth need timing/backpressure analysis. **Inference, not established fact:** sustained decoding/transport contention may cause the queue overload and apparent timestamp jumps. Capture, socket reader, Python chunking, worker writer, and macOS scheduling must be instrumented before choosing a fix. The combined transcript includes speaker playback twice because the mic heard the Mac speakers. `word_end_delay_proxy_ms` uses recognizer word timestamps; it is **not** independently annotated utterance-end latency.

`spikes/LIVE_CAPTURE.md` currently says the 30-minute native test is “In progress” and is stale. Update it with the failed outcome before treating it as the current acceptance report. Do not hide or overwrite the failure artifact.

## Important technical decisions and rejected approaches

Directly launching `.build/CrackitProbe.app/Contents/MacOS/CrackitProbe` as a Python child was denied Screen Recording even when the GUI had permission. The live harness uses `open -n -a ... --args` and a `/private/tmp` Unix socket so LaunchServices supplies the app’s TCC identity. A FIFO passed with `open -o` was rejected. The native app is currently **ad-hoc signed**; rebuilding it invalidated its Screen Recording grant and caused a permission loop. `spikes/native/build.py` supports `CRACKIT_CODESIGN_IDENTITY`, but this Mac had no Apple Development identity. **Do not rebuild the current app just to rerun tests** unless prepared for a fresh grant and restart. The diagnostic opens by user action; capture must not auto-start when an interview app opens.

The v2 worker emits `ready` after model/VAD initialization; `SourceRouter.prepare()` prewarms selected decoders before capture. Per-source epochs and explicit gaps prevent stale provisional text from becoming evidence after overload or timestamp jumps. `spikes/live_native.py` now marks reported gaps or missing controlled signal as `incomplete`; the pre-hardening 65-second report’s `completed` label remains historically misleading. The worker is pinned to whisper.cpp v1.9.5 commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`, local `base.en` model checksum `a03779c86df3323075f5e796cb2ce5029f00ec8869eee3fdfb897afe36c6d002`, and local Silero VAD. Verify model/checkouts before replacing them. CPU is the measured baseline, not a proven best production backend.

An own-window magenta marker was absent with ScreenCaptureKit sharing `.none` on the **selected-window** test. This does not establish full-display, Zoom/Teams/Meet, remote-recipient, screen-recorder, or cross-platform exclusion. No honest universal “stealth” claim follows. Voice/name tests found wrong owner/name substitutions even when aggregate WER looked acceptable; a roster spelling is a suggestion requiring identity confirmation. Citation IDs can be valid while an answer misses the question. Final-only evidence and request cancellation must remain intact when building the answer path.

Hosted evaluation is halted after two incomplete AssemblyAI comparison sessions with unconfirmed usage; the user reported no dashboard warning/balance detail. `spikes/providers.py` and the ledger preserve reservations and a halt file. The user authorized **up to $10 of verified free/credit-covered nominal usage, with $2 possible-cash ceiling**. They confirmed Gemini Free Tier and AssemblyAI’s advertised $50 credit, but AssemblyAI remaining balance/auto-pay and actual charges have not been reconciled. Do not reset ledger/halt, raise limits, change billing, or silently restart hosted runs. Keys belong in local `.env`, never in chat or Git. DeepSeek V4.1 Flash is a candidate model, not a selected default; no provider/model quality or price advantage is established for the finished product.
