# Interview-first native capture validation

Date: 2026-10-09. This is a local diagnostic on one Apple M1 Mac running macOS 26.5.1, not a production acceptance report. The generated interview fixture is scripted, non-overlapping macOS speech synthesis. No customer audio or screenshots were used; PCM moved through a local Unix socket and was not saved or uploaded. Transcripts and health reports are under ignored `spikes/results/local/native/`.

## Capture path and permission finding

`CrackitProbe` uses ScreenCaptureKit for system and optional microphone sample buffers. `LiveFrames.swift` converts each source to 16 kHz mono PCM and reports buffer counts, RMS, converter errors, and timestamp gaps. `live_native.py` launches the app through LaunchServices, validates frames, sends bounded chunks to independent v2 decoder epochs, and records final text by source. Directly starting the bundle executable from the Python harness was denied Screen Recording despite permission in the GUI; LaunchServices reported the permission correctly. Rebuilding the ad-hoc signed app also invalidated its prior grant. A stable Apple Development signing identity should replace ad-hoc signing for repeated development; none was available on this Mac. [Apple code-signing identity guidance](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

The repaired worker now emits a readiness event after model and VAD loading. The router prewarms selected sources **before** native capture starts, so model loading cannot fill the two-second input queues. The current report marks any explicit gap or missing controlled phrase as incomplete. The microphone and system streams are kept separate; combining their text would duplicate the known playback. The microphone requires headphone/isolation and echo handling before it can be treated as an independent local speaker.

The failed 30-minute artifact is preserved under `spikes/results/local/native/`. Its native report has zero converter errors, one mic timestamp gap over 100 ms, and zero such system gaps. Python reports one discontinuity for each source using a 20 ms tolerance and a different clock calculation. The native stderr file is empty. `worker-logs/` is shared across runs and contains timestamps beyond this capture, so those files cannot be attributed reliably to the failed run. Current metrics do not identify whether capture stalled, socket writes backed up, Python routing blocked, or decoder throughput fell behind. The 1,860 s duration also exceeds the 1,805 s request; instrument each stage before choosing a repair. Preserve explicit gaps and the failed artifact.

Subsequent diagnostic code records native callback and socket-write maxima, per-source socket-receive and routing timing, decoder queue age/write timing including retired epochs, and periodic process CPU/RSS samples. New worker logs use a unique directory per run. A 15-second system-only check with the previous app binary passed (`live-15s-system-diagnostics.json`). Rebuilding the ad-hoc signed app for native timing invalidated its Screen Recording grant: `live-15s-system-native-timing.json` is **incomplete with zero captured frames** and a TCC denial. Regrant and verify permission with a short run before attempting sustained capture; neither short check resolves the 30-minute failure.

Quitting the older Probe and retrying while the existing System Settings switch remained enabled also failed: `live-15s-system-native-timing-after-quit.json` records zero frames and the same TCC denial. The user was asked to remove the stale entry and add the current rebuilt app bundle. Do not count either denied attempt as a capture test or start endurance testing until a fresh short run verifies permission.

After the current app was added, `live-15s-system-native-timing-granted.json` passed: 790 system buffers, no gap/error, expected phrase recognized, and native/transport/resource timings populated. The first instrumented 30-minute **system-only** run (`live-30m-system-instrumented.json`) is **incomplete**: ScreenCaptureKit stopped at about 1,508 seconds with “Failed to find any displays or windows to capture.” `pmset -g log` records the display turning off at 21:15:15 local time, about 25 minutes into the run. Before that transition, the decoder remained in epoch 0, with a peak queue of two chunks, maximum queue age 8.9 ms, no transport discontinuities, and no socket write over 100 ms. The native report contains 24,134,394 samples (about 1,508 seconds) and the surviving transcript has 608 edits / 3,739 reference words; this is missing-end coverage, not a complete accuracy measurement. Preserve this as a display-sleep failure. Repeat controlled throughput testing with idle display sleep prevented, then test sleep and recovery separately.

The awake **system-only** repeat (`live-30m-system-awake.json`) completed with `caffeinate -di` active and the same WAV SHA-256 `5ac519725d9f8656b9c8f314eb3a2db8b4c097250e07c61134bc3cba9f241feb`. It had no gaps, discontinuities, converter errors, or decoder resets; all 202 scripted finals and the closing turn survived. System PCM covered 1,863.7 seconds, maximum decoder queue was two chunks, maximum queue age 5.7 ms, and maximum native socket write 6.2 ms. The surviving system transcript had 35 edits / 3,739 reference words (0.94% WER). Across 371 samples, the decoder RSS peaked near 284 MiB and ended near 266 MiB; native RSS stayed near 29 MiB. This passes the controlled sustained **single-source, awake** continuity check, not dual-source or sleep recovery. Native capture lasted 1,863.9 seconds despite a 1,805-second request; the cause of the roughly 59-second overrun is unmeasured and requires stop-phase timing before product acceptance.

## Open acceptance boundaries

Even a clean 30-minute scripted run would not establish real interview accuracy, speaker separation, exact utterance-end latency, screen-share exclusion, device-switch recovery, or thermal/battery suitability. The reported word-end delay is a proxy from recognizer timestamps, not independently annotated speech-end latency. Follow this with consented live conversation, headphones/speakers comparisons, overlapping turns, and device/permission transition tests. Do not advertise universal stealth or perfect interview performance from these fixtures.
